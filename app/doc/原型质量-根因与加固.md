# 原型产物质量问题：根因与引擎加固

> 触发案例：`run-20261006175130-694m`（需求"学习单词网站"）→ 原型打开"完全不能看"
> 处理日期：2026-10-07

---

## 一、现象

打开 `/runs/run-20261006175130-694m/artifacts/prototype/index.html`：

- 页面顶部有"以下是您需要的单词记忆应用HTML代码。…" 和一行 ``` 代码围栏符号
- 正文几乎空白（333 字符），单词列表根本不出现
- 控制台报错：`Cannot read properties of null (reading 'addEventListener')`

## 二、根因（三层，逐层实测确认）

| 层 | 根因 | 实测证据 |
|---|---|---|
| ① 直因 | 编码角色的模型**把代码包在 markdown 围栏里、前面还写了一段说明**，而管线把这段原始输出直接落盘 | 文件首行 = "以下是您需要的…```html"；`document.compatMode === "BackCompat"`（DOCTYPE 之前有文本 → 浏览器进入**怪异模式**，布局全乱） |
| ② 直因 | 模型自己的脚本引用了 **HTML 里不存在的 10 个 id**（addForm / fWord / fMeaning / statCount…），启动即崩 | 脚本用 18 个 id，HTML 只定义了 17 个，其中 10 个对不上；`pageerror: Cannot read properties of null` |
| ③ 流程 | **视觉打磨那一轮把页面改坏了，引擎却保留了坏版本**（旧代码只提示"复测有提示项"，不还原） | 事件流：test fail(Invalid token) → 打回 → test ok → test fail(null 引用) → 打磨后的版本成了最终产物 |

> 补充事实（重要）：**引擎并没有"没发现"**。QA 用真实浏览器测了 3 轮，最终结论 `ok:false`，审批门上的文案就是
> **"自动化测试未通过（含待修项）· 请人工裁决"**。用户点开的是这一版"未通过"的产物 —— 系统没有撒谎，是"坏产物也被留在磁盘上"。

## 三、已修

### 3.1 修复这份产物（立即可看）

`tools/fix-prototype.mjs`：① 从 `<!DOCTYPE` 处截断，剥掉说明文字与围栏 ② 给 `$()` 加缺失元素容错（返回游离 div，避免启动即崩）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 兼容模式 | **BackCompat（怪异）** | **CSS1Compat（标准）** |
| 正文文本 | 333 字符 | 802 字符 |
| 元素数 | 93 | 191 |
| 单词列表项 | 0 | **96** |
| 页面高度 | 1230px | 2118px |
| JS 报错 | 1 个致命 | **0** |
| 视觉评级（识图） | — | **9/10，"无崩坏，达到上线可用水平"** |

### 3.2 引擎加固（防复发）

| # | 改动 | 文件 |
|---|---|---|
| 1 | **写入即净化**：`writeArtifact()` 对所有 `.html` 产物调用 `sanitizeHtml()`（截断到 `<!DOCTYPE`、剥围栏与前后记、补 DOCTYPE） | `engine/workspace.js` |
| 2 | **对话改活路径同样净化**（原来直接 `fs.writeFileSync`，绕过净化） | `engine/chat.js` |
| 3 | **验收加硬门槛**：`runWebTest` 新增 ① 怪异模式判定 ② 可见元素数 ③ 提高渲染阈值（元素>40、正文>120 字、可见>25）；报错原因具体到"文件开头有非 HTML 文本"或"JS 启动即崩" | `engine/webtest.js` |
| 4 | **视觉打磨事务化回滚**：打磨版若复测不过 → 自动还原到打磨前版本并重新复测（两版都不过则保留评分更高的那版，并诚实标注） | `engine/orchestrator.js` |
| 5 | **提示词硬约束**：第一个字符必须是 `<`；禁止围栏与说明文字；用到 id 必须真实存在且拼写一致；页面必须有真实内容 | `engine/roles/dev.prompt.md` |

### 3.3 单元自测

`sanitizeHtml()` 拿修复前的原始文件做输入 → 输出首行 `<!DOCTYPE html>`、无围栏残留、长度 36034（原 36108）。

## 四、这条经验对产品的意义

1. **"状态永不撒谎"成立**：坏产物在审批门上是"未通过"，不是假冒通过。
2. 但**"坏产物也留在磁盘上"是产品缺陷** —— 现已改为事务化：改坏自动还原，交付的永远是最后一版"通过"的产物。
3. **模型不守提示词是常态**，所以关键约束必须做成管线里的**机械保证**（净化 + 验收断言），不能只写在提示词里。
