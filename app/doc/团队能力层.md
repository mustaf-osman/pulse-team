# 团队能力层：记忆 / 视觉 / 真工具链

> 让 AI 团队"和我一样强"的唯一办法：**把我用的东西给它**——记忆、眼睛、真工具、回炉。
> 模型本身不会变强，**管线会**。

---

## 一、记忆（`engine/memory.js`）
模型每次调用都是白纸。解决办法：把每轮经验**沉淀成文本，下轮按相关性注入提示词**。

- 存储：`G:/pulse-team/data/memory/roles/<角色>.md`（每角色最多 60 条）+ `project.md`（80 条）
- 格式：`- [日期] [标签] 内容`，自动去重（同前缀不重复写）
- **写回**（确定性，不额外调模型）：每轮跑完自动沉淀
  - 设计审计发现（内容列过窄 / emoji 图标 / CSS 类名命中率低 / 对比度不足 / 字号过碎 / 横向溢出）
  - 浏览器测试失败原因、点测问题、人工打回意见
  - 视觉评审意见、本次产出清单
- **读取**：加载角色时把该角色 + 项目的记忆按**相关性**（关键词重合 + 教训加权）取前 6 条，附到系统提示词末尾；`generateHtml()` 里还会按当次任务文本再取一次（更贴题）
- 实测：写入 8 条 → `recall('dev','写学习数学网站，注意排版和对比度')` 正确把"内容列 47% 要改 1200""CSS 命中率 28%""对比度 2.1"排在最前

## 二、视觉评审（`engine/vision.js`）—— 给团队装眼睛
以前只有 DOM 断言（"量"），没有"看"。现在：
1. Playwright 截 **桌面 1440 + 手机 390** 两张图，落进产出物（UI 里能点开看）
2. 送 **qwen-vl-max** 做结构化评审，只出 JSON：`{score, verdict, issues[], highlights[]}`
3. `score < 70` → 带意见**回炉一轮**（改完必须设计分上涨且视觉分不下降，否则回滚）
- 实测（你那个"学习数学网站"原始版）：**30 分 ·"未完成的原型，不可交付"**，并指出
  「顶部导航无实际内容」「页面主体空白过多」「**颜色定义存在但未应用到元素**」「字体大小统一，无层级」——与我在代码层查到的 CSS 接线问题**完全吻合**

## 三、真工具链（`engine/verify.js`）—— 从"能看"到"能交付"
装的是业界真工具（npm 已装），不是自己写的断言：

| 工具 | 作用 | 实测结果 |
|---|---|---|
| **html-validate** | HTML 规范（隐式闭合、缺 `type="button"`、重复 id、`<img>` 无 alt…） | 抓到 15 个错误 |
| **axe-core** | **无障碍审计（WCAG 2.0 A/AA 业界标准）**：对比度、可访问名称、语言、角色 | 0 违规 |
| **esbuild** | **编译器级**语法检查（JS/CSS 编译失败即报错）+ 压缩打包 | 编译通过；打包 71.9KB → **65.8KB** |

**打包产物**：`artifacts/dist/index.html`（零依赖单文件，双击即用）+ `dist/README.md`（交付说明：怎么部署、质量记录、体积）
→ 这就是"产出可以完整使用"：**规范过、无障碍过、可编译、可部署**。

**严重问题回炉**：编译失败 / axe 严重项 / HTML 错误 >6 → 带"编译器原始报错"回炉一轮，复测更好才采纳，否则回滚。

## 四、跑一轮现在会发生什么（新管线）

```
需求 → PM → 需求分析 → 方案设计(带记忆)
   → 编码(带记忆+UI保证层) → 真浏览器测试 → 视觉打磨(回滚保护)
   → ① 设计审计(量化打分, <78 带问题重做) 
   → ② 视觉评审(真看图, <70 带意见重做)
   → ③ 真工具校验(html-validate/axe-core/esbuild) + 严重项修复
   → ④ 打包 dist/index.html + README(可部署)
   → 测试报告 → 交付文档 → 人工审批 → 记忆写回
```
每一步都：**量出问题 → 带证据回炉 → 复测更好才采纳 → 否则回滚**。

## 五、关于 Grok Build（说清楚，别糊弄）
`xai-org/grok-build` **是真实存在的**：xAI 官方开源的编码 Agent（全屏 TUI、headless、ACP、支持 AGENTS.md/MCP），和我们用的 Claude Code 同类。
但它**不是编译器**，也不会自动让产出变好看——它是"另一个会写代码的 Agent"。

两条可选路线（需要你定）：
1. **当"硬骨头升级通道"**：给团队加一个"编码升级器"——需求复杂时把活派给 `grok` CLI / `claude` CLI（它们能读整个仓库、跑构建、自己跑测试），产出交回团队验收。**前提：要有 xAI 或 Anthropic 的 key**。
2. **继续走现在的路**（已落地）：真工具校验 + 编译器级检查 + 无障碍审计 + 打包，把"能交付"变成机械保证。
   —— 这条不需要额外付费 key，且已经被实测证明有效（同一批产出平均分 50 → 74，纯代码无 LLM）。
