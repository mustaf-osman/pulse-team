# Pulse — 多 Agent 虚拟软件团队

> **一句话需求 → 六个 AI 角色协同 → 真实可运行的产品原型 → 人工审批放行**

Pulse 是一套**多 Agent 协同交付系统**。你给一句话需求，六个专业化 AI 角色像一支真实的软件团队一样分工协作，产出可运行的交付物（单文件 HTML 原型 + 测试报告 + 交付文档 + 交付证书），全程有人工审批关卡。

不是"一问一答的聊天机器人"——是一个**有组织、有分工、有质量门禁、有交付标准**的 AI 软件团队。

---

## 🧑🤝🧑 六个 Agent 角色

每个角色是独立的 Agent，有自己的职责边界、提示词、模型路由和温度参数：

| 角色 | ID | 职责 | 模型路由 | 温度 |
|------|:--:|------|:--:|:--:|
| 项目经理 | `pm` | 拆解需求 → 指派任务 → 把控范围 | 主模型 | 0.5 |
| 需求分析师 | `req` | 把需求写成正式需求文档（FR 编号） | 主模型 | 0.6 |
| 方案设计 | `des` | 页面结构 / 信息架构 / 交互设计 | DeepSeek | 0.6 |
| 编码开发 | `dev` | 产出可运行的单文件 HTML 原型 | DeepSeek | 0.4 |
| 测试工程 | `qa` | 自动化测试（真实操作浏览器） | 主模型 | 0.4 |
| 文档工程 | `doc` | 交付文档 / 使用说明 | 主模型 | 0.6 |

**关键设计：模型按角色路由。** 编码类角色走 DeepSeek（便宜且代码强），决策类角色走主模型（综合能力更强）。这就是编排器的"多模型路由"。

## ✨ 核心能力

### 多 Agent 编排

- **六角色分工**：每个角色有独立提示词（`engine/roles/*.prompt.md`）和 JSON 输出契约
- **模型路由**：按角色分配不同 provider/model，成本与质量平衡
- **真并行**：测试用例预写，缩短串行等待
- **检查点续跑**：中断后可从检查点恢复，不用从头重来

### 质量门禁（不只是"生成完就交"）

| 模块 | 作用 |
|------|------|
| `designaudit.js` | 设计审计——版式宽度、字号、圆角规范 |
| `coverage.js` | 覆盖率审计——需求点是否都被实现 |
| `quality.js` | 质检 |
| `redteam.js` | 红队审查——主动找问题 |
| `vision.js` | 视觉评审——看渲染效果 |
| `verify.js` | HTML 校验 + axe 无障碍检测 + 编译检查 |
| `webtest.js` | 真实浏览器自动化测试 |
| `certificate.js` | 签发交付证书 |
| `gitrepo.js` | Git 版本记录——每次交付可追溯 |

### 人工介入

- **审批门（Gate）**：关键节点停下来等你确认，可打回带意见
- **停止按钮**：随时叫停，不用等它跑完
- **断点续跑**：中断后恢复

### 记忆与学习

- `memory.js`：跨运行的团队记忆——记住项目上下文、角色经验
- 每次交付后从运行中学习，下次更准

## 🚀 快速开始

```bash
cd app
npm install
npm start
# 打开 http://localhost:3000  → 多 Agent 工作台
```

**然后：** 在界面输入一句话需求，看六个 Agent 依次上场干活。

### API

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/api/run` | 开工：`{ requirement }` 一句话需求 |
| `GET` | `/api/state` | 当前运行状态（哪个 Agent 在干活） |
| `POST` | `/api/gate` | 审批关卡：`{ approve }` 放行或打回 |
| `POST` | `/api/stop` | 停止当前运行 |
| `POST` | `/api/resume` | 从检查点续跑 |
| `GET` | `/api/runs` | 历史交付记录 |
| `GET` | `/api/runs/:id/report` | 某次交付的完整报告 |
| `GET` | `/api/memory` | 团队记忆 |
| `GET` | `/api/routes` | 各角色的模型路由配置 |

## 💡 为什么这么做

单个 Agent 干复杂活容易跑偏、忘记上下文、没人把关。Pulse 的答案是：

1. **分角色** —— 每个 Agent 只干一件事，提示词更精准、输出更稳定
2. **串成流水线** —— 上一个角色的产出是下一个的输入，形成可追溯的链
3. **加质量门禁** —— 不靠"生成完就算完"，而是审计、测试、红队、覆盖率检查
4. **留人工关卡** —— 关键决策留给人，AI 不负最终责任
